# 界面与交互规范

本文定义 Doris SQLTools Lite 在 VS Code 中的统一界面基线。连接、参数、计划和结果页是一个连续工作台的不同任务页面，共用层级、状态、操作区和响应式规则。视觉验收以本文和 [发布检查清单](release-checklist.md) 为准。

## 设计目标

界面围绕“当前任务、当前对象、下一步操作”组织：

- 用户进入页面后先看到在操作什么、连接到哪里、当前处于什么状态。
- 参数、连接、模式和产物路径出现在提交动作附近，方便提交前核对。
- 成功、警告、失败、截断和收尾状态使用稳定位置与一致措辞。
- 桌面宽窗口和 VS Code 窄侧栏使用同一信息顺序，只调整列数和密度。
- 键盘、鼠标、触摸板和屏幕阅读器都能完成主工作流。

## 共享页面结构

四个 Webview 统一使用 `src/webviewTheme.ts` 中的主题和结构：

1. **页头**：任务标题、简短说明和页面级徽章。
2. **状态区**：成功、警告、错误和进行中信息，使用 `aria-live` 播报。
3. **分区**：相关字段或内容进入同一张卡片，标题说明这一组要完成什么。
4. **主体**：表单、代码、计划或结果表；长内容在自身区域内滚动。
5. **固定操作栏**：主操作、次操作和状态反馈保持在可见范围。

页面标题使用任务语言，例如“添加连接”“确认查询参数”“执行计划”“查询结果”。命令 ID、协议字段和设置键保持准确写法。

## 视觉语言

颜色、字体、输入框、按钮和焦点使用 VS Code 主题变量，自动跟随浅色、深色与高对比主题。共享样式负责：

- 8px 主圆角与 5px 控件圆角。
- 页面渐变背景、分区表面和柔和边框形成的层级。
- 主按钮、次按钮、幽灵按钮和禁用状态的一致差异。
- 稳定字号、行高、间距和表单最小高度。
- 仅在颜色之外同时使用文字、图标或边框表达状态。

扩展不覆盖 VS Code 的字体族。代码和计划使用编辑器字体；普通说明使用 VS Code 界面字体。

## 页面职责

### 连接页

- 快速导入放在第一分区，减少手工填写。
- 连接目标、传输安全和密码策略按任务顺序排列。
- 类型切换即时更新默认端口和适用字段。
- 测试连接、保存、取消在固定操作栏中保持可见。
- 密码为空时解释“保留原密码”或“暂不保存”的实际含义。

### 参数页

- 顶部显示来源文件和缺失参数数量。
- 参数列表显示名称、来源、当前值和只读状态。
- 实际发送 SQL 使用独立代码区，长 SQL 在区域内滚动。
- 取消、提交和返回编辑器的结果明确。

### 计划页

- 页头显示名称、连接类型、数据库和来源行号。
- 计划正文保留缩进与等宽显示。
- 复制反馈、保存反馈和完整材料动作清楚区分。
- 计划较长时操作栏保持可见，正文独立滚动。

### 结果页

- 页头显示名称、连接、数据库、耗时、行数、列数和模式。
- 截断、读取上限、参数和警告使用徽章或状态区表达。
- 表格首列与表头保持可辨认，多列内容在表格内部横向滚动。
- 筛选、排序、复制、导出和反馈动作在固定操作栏中排列。
- 零行结果保留列结构并显示空状态。

### 通知与状态栏

- 有结果集的查询打开结果页。
- 无结果集的 DML、DDL、`USE`、`SET` 使用完成通知。
- 长任务通知持续显示当前阶段、对象和取消入口。
- 状态栏显示当前连接、运行状态和字段模式，文案与页面一致。

## 状态模型

每个页面在实现和测试中覆盖以下状态：

| 状态 | 界面表达 | 用户可执行动作 |
| --- | --- | --- |
| 初始 | 字段、说明和主操作完整可见 | 填写、选择或取消 |
| 进行中 | 状态区说明当前步骤，重复提交入口禁用 | 等待或取消 |
| 成功 | 完成信息、实际产物和下一步入口 | 查看、复制、保存或关闭 |
| 空结果 | 保留页头、列头和空状态 | 返回编辑器或重新查询 |
| 截断 | 显示已读取行数、预览上限和截断徽章 | 导出完整结果或重新查询 |
| 警告 | 使用警告样式说明兼容模式、清理结果或未知状态 | 核对后继续 |
| 失败 | 错误类别、可操作建议和失败阶段集中显示 | 修改输入、重试保存或关闭 |
| 已取消 | 明确操作停止位置，保留已完成信息 | 核对结果后继续 |
| 清理残留 | 显示残留路径和文件用途 | 手工核对并清理 |

状态文案描述已经发生的事实，并给出下一步动作。错误说明区分参数、连接、认证、SQL、写入、取消和清理阶段。

## 响应式布局

| 可用宽度 | 布局规则 |
| --- | --- |
| 1080px 以上 | 居中内容区，表单最多两到三列，结果页使用宽布局 |
| 681px 到 1079px | 内容区随窗口缩放，表单自动减少列数 |
| 680px 以下 | 页头和表单转为单列，操作栏允许换行 |
| 420px 以下 | 徽章换行，按钮保持可读，长路径和代码在容器内滚动 |
| 320px | 最小验收宽度，页面级横向滚动为 0 |

页面本身不产生横向滚动。结果表、SQL、计划和长路径在各自容器内滚动。

## 可访问性

- 所有输入都有可见标签，相关说明与控件建立关联。
- 焦点顺序跟随视觉顺序，焦点环使用 VS Code `focusBorder`。
- 状态区使用 `aria-live`，错误与成功信息可被屏幕阅读器播报。
- 按钮在操作进行中使用 `disabled`，同时保留当前阶段说明。
- 表格提供列名和可理解的排序状态。
- 只在颜色之外表达状态，避免仅靠红绿区分。
- `prefers-reduced-motion` 开启时关闭过渡和动画。
- 320px 宽度、200% 缩放和键盘单独操作都能完成主流程。

## 文案规则

- 命令和按钮以动作开头，例如“添加连接”“执行光标处 SQL”“导出 TSV”。
- 同一概念只使用一个名称：连接、参数、会话、执行计划、字段密文、字段原文。
- 输入说明先讲字段是什么和怎么使用，再补充适用范围。
- 错误先说明失败动作和原因，再给出下一步。
- 内部实现词留在日志和开发文档，用户界面使用任务语言。
- 连接类型、SQL 关键字、配置键、命令 ID 和产物路径保持准确写法。

## 验收流程

1. 运行 `pnpm test`，通过 Webview 结构和脚本检查。
2. 运行 `pnpm run preview:webviews`，生成四个真实页面。
3. 在 1200px、720px、420px 和 320px 检查布局。
4. 分别检查浅色、深色、高对比主题和 200% 缩放。
5. 仅用键盘完成连接、参数确认、计划查看和结果导出。
6. 检查进行中、成功、空结果、截断、失败、取消和清理残留状态。
7. 确认页面级横向溢出为 0，结果表在自身区域滚动。

影响共享结构或用户可见文字的改动，需要同时更新本文、相关使用文档和 Webview 契约测试。
