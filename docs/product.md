# 产品定位与 1.0 承诺

## 产品定义

Doris SQLTools Lite 是面向 VS Code 的轻量 SQL 工作台，服务于 MySQL、Apache Doris 与 Spark Thrift。它把文件中的 SQL、已有连接、参数、会话、结果、执行计划和错误诊断收敛到一个输出面。

产品聚焦五件事：

1. 在 SQL 文件里直接执行光标所在语句，保留文件作为唯一 SQL 入口。
2. 结果、执行计划和执行错误进入同一个输出面板；结果/计划/错误用按需 Tab 切换，不维护两套动作。
3. 复制只有两种：`origin` 纯内容，`extra` 引用与上下文；导出只负责完整产物。
4. SQL 正文不进入复制包，只给文件引用，让 AI 按行号读取。
5. 字段保护由 SQL 注释声明，AI 通过 skill 生成声明，扩展只在结果输出中执行。

## 目标用户

- 经常在 VS Code 中维护分析 SQL、补数 SQL 和临时排查 SQL 的个人开发者。
- 同时接触 MySQL、Doris 和 Spark Thrift，希望用同一套文件、参数和输出习惯的人。
- 经常把 SQL 和计划交给 AI 审核，也需要把结果原样贴进表格或下游工具的人。

## 产品原则

### 明确优先

连接、参数和预览上限都写在当前操作可见的位置。发送给数据库的 SQL 可以在参数页核对；结果、计划和错误共享复制/导出动作。

### 文件优先

SQL 文件是工作起点。连接注释、参数注释、命名、输出路径和批次步骤都跟着文件走；扩展不建立另一套查询历史或 SQL 仓库。

### 本地优先

密码进入 VS Code SecretStorage，连接元数据留在用户设置，参数与字段密钥留在本机扩展存储。扩展默认不发送 SQL、结果、计划、错误诊断或参数到远端服务。

### 结果可核对

复制包使用文件引用和明确字段。未知总行数、未知影响行数、会话丢失、来源改动和未完成文件都保留显式状态。

### 中断可恢复

查询、计划和批次都可以取消。执行中的写入采用顺序提交，扩展停止后续步骤并保留已完成步骤；恢复由用户根据实际状态决定。

### 界面统一

连接、参数和输出面板使用同一套页头、徽章、分区、状态提示、操作栏和响应式规则。结果、计划和错误只是输出面板的按需 Tab。

具体基线见 [界面与交互规范](ux.md)。1.0 前，三个页面和三个输出 Tab（错误按需出现）在宽窗口、窄侧栏、浅色、深色、高对比主题以及纯键盘操作下都按同一份状态模型验收。

## 1.0 的用户承诺

### 稳定性

- 三个数据库适配器共享清楚的会话、取消、结果和错误语义。
- 正常路径、取消路径、断线路径和磁盘失败路径都有自动化测试。
- 声明支持的最低 VS Code 版本会运行真实集成测试。

### 可理解性

- 常用工作流可以从 README 和 `docs/usage.md` 直接完成。
- 命令、设置、状态栏、Webview 和错误提示使用一致的中文。
- `@copy: origin` 与 `extra` 的复制内容有稳定字段和示例。

### 可恢复性

- 写文件采用临时文件加完成点，已有目标不被覆盖。
- 失败、取消、会话丢失和清理失败分别报告。
- 取消后不会悄悄重试 SQL，也不会把未知写入说成成功。

### 安全性

- 密码与字段密钥分开存储。
- TLS 默认校验证书；主动放宽校验需要明确操作。
- 不可信工作区可以查询和查看结果，运行工作区脚本需要工作区信任。

### 可维护性

- 共享 Webview 主题、复制契约、版本兼容基线和发布检查都在仓库中维护。
- 自动化测试覆盖本机工作流，并能按 VS Code 最低版本启动真实集成测试。
- 构建、打包和发布检查使用一条可重复的命令链。

## 1.0 的完成标准

发布 `1.0.0` 前需要同时满足：

- MySQL、Doris、Spark Thrift 各自完成至少一次非生产实例验证。
- 从 `0.9.x` 升级与干净安装都能加载同一功能集。
- 全部自动化测试、lint、Webview、bundle、文档一致性、打包和最低版本集成测试通过。
- 发布候选版本完成一轮真实使用观察，没有阻断主流程的已知缺陷。
- README、使用说明、安全说明、复制契约、开发说明和变更日志与当前版本一致。

0.9.x 阶段继续遵循“一次交付解决一组可独立验收的问题”。每个阶段完成后更新版本、CHANGELOG、README 和本机安装状态；影响工具使用的行为变化再同步 skill。

`0.9.10` 至 `0.9.15` 的自动化与本地集成测试结果只证明仓库内检查通过。真实 Doris、Spark Thrift、TLS 证书目标、升级、干净安装和实际工作流观察分别记录结果，全部达到 1.0 完成标准后才发布 `1.0.0`。

## 版本策略

`1.0.0` 表示工作流、命令 ID、复制契约、配置键和安全边界进入稳定契约。后续新增字段可以保持向后兼容；删除字段、改变含义或重命名命令 ID 需要新的主版本。

功能增强进入 `1.x`，补丁版本用于修复和兼容改进。字段加密格式 `enc:v1` 独立演进；旧反馈 schema 只保留兼容。

## 1.0 之后的候选方向

- 更丰富的对象浏览与 SQL 编辑辅助。
- 更强的批量任务观察、恢复和审计能力。
- 更多结果格式与下游数据交换方式。
- 可选的企业连接入口、代理和密钥管理集成。

这些方向以真实痛点和新契约需要为前提，不改变 1.0 已承诺的本地优先与显式操作原则。
