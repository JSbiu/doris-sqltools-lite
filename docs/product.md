# 产品定位与 1.0 承诺

## 产品定义

Doris SQLTools Lite 是面向 VS Code 的轻量 SQL 工作台，服务于 MySQL、Apache Doris 与 Spark Thrift。它把文件中的 SQL、已有连接、参数、会话、结果文件、执行计划和 AI 审核材料串成一条可核对的本地工作流。

产品聚焦五件事：

1. 在 SQL 文件里直接执行光标所在语句，保留文件作为唯一 SQL 入口。
2. 提交前看清实际连接的数据库、实际参数和实际发送的 SQL。
3. 结果既能快速预览，也能一次流式导出完整 TSV。
4. 长查询、计划、分批补数和字段保护都有明确状态，失败后保留可核对证据。
5. 扩展显式生成 AI 材料，用户决定复制、保存和交给哪个工具。

## 目标用户

- 经常在 VS Code 中维护分析 SQL、补数 SQL 和临时排查 SQL 的个人开发者。
- 同时接触 MySQL、Doris 和 Spark Thrift，希望用同一套文件、参数和反馈习惯的人。
- 需要把完整结果、执行计划或字段密文交给下游流程，同时要能追溯来源和状态的场景。

## 产品原则

### 明确优先

连接、参数、模式和预览上限都写在当前操作可见的位置。发送给数据库的 SQL 可以在参数页核对；计划、导出和批次摘要都记录来源与状态。

### 文件优先

SQL 文件是工作起点。连接注释、参数注释、命名、输出路径和批次步骤都跟着文件走；扩展不建立另一套查询历史或 SQL 仓库。

### 本地优先

密码进入 VS Code SecretStorage，连接元数据留在用户设置，参数与字段密钥留在本机扩展存储。扩展默认不发送 SQL、结果、计划或参数到远端服务。

### 结果可核对

反馈使用固定 schema 和明确字段，产物通过绝对路径引用。未知总行数、未知影响行数、会话丢失、来源改动和未完成文件都保留显式状态。

### 中断可恢复

查询、计划和批次都可以取消。执行中的写入采用顺序提交，扩展停止后续步骤并保留已完成步骤；恢复由用户根据实际状态决定。

### 界面统一

连接、参数、计划和结果页使用同一套页头、徽章、分区、状态提示、操作栏和响应式规则。界面用词围绕用户正在完成的任务组织。

具体基线见 [界面与交互规范](ux.md)。1.0 前，四个页面在宽窗口、窄侧栏、浅色、深色、高对比主题以及纯键盘操作下都按同一份状态模型验收。

## 1.0 的用户承诺

### 稳定性

- 三个数据库适配器共享清楚的会话、取消、结果和错误语义。
- 正常路径、取消路径、断线路径和磁盘失败路径都有自动化测试。
- 声明支持的最低 VS Code 版本会运行真实集成测试。

### 可理解性

- 常用工作流可以从 README 和 `docs/usage.md` 直接完成。
- 命令、设置、状态栏、Webview 和错误提示使用一致的中文。
- 反馈 JSON 有独立的版本化契约和可复制示例。

### 可恢复性

- 写文件采用临时文件加完成点，已有目标不被覆盖。
- 失败、取消、会话丢失和清理失败分别报告。
- 取消后不会悄悄重试 SQL，也不会把未知写入说成成功。

### 安全性

- 密码与字段密钥分开存储。
- TLS 默认校验证书；主动放宽校验需要明确操作。
- 不可信工作区可以查询和查看结果，运行工作区脚本需要工作区信任。

### 可维护性

- 共享 Webview 主题、反馈 schema、版本兼容基线和发布检查都在仓库中维护。
- 自动化测试覆盖本机工作流，并能按 VS Code 最低版本启动真实集成测试。
- 构建、打包和发布检查使用一条可重复的命令链。

## 1.0 的完成标准

发布 `1.0.0` 前需要同时满足：

- MySQL、Doris、Spark Thrift 各自完成至少一次非生产实例验证。
- 从 `0.9.x` 升级与干净安装都能加载同一功能集。
- 全部自动化测试、lint、Webview、bundle、文档一致性、打包和最低版本集成测试通过。
- 发布候选版本完成一轮真实使用观察，没有阻断主流程的已知缺陷。
- README、使用说明、安全说明、反馈 schema、开发说明和变更日志与当前版本一致。

## 稳定化轨道

| 阶段 | 目标 |
| --- | --- |
| `0.9.9` | 文档、反馈契约、最低 VS Code 类型和本地集成测试收口 |
| `0.9.10` | 发布候选：真实 MySQL/Doris/Spark 非生产验证、升级与干净安装、文档冻结 |
| `1.0.0` | 候选版本完成使用观察，阻断缺陷清零，契约与发布材料确认 |

0.9.x 阶段继续遵循“一次交付解决一组可独立验收的问题”。每个阶段完成后更新版本、CHANGELOG、README、skill 和本机安装状态。

## 版本策略

`1.0.0` 表示工作流、命令 ID、反馈 schema v1、配置键和安全边界进入稳定契约。后续新增字段可以保持向后兼容；删除字段、改变含义或重命名命令 ID 需要新的主版本。

功能增强进入 `1.x`，补丁版本用于修复和兼容改进。字段加密格式 `enc:v1` 与反馈 `schemaVersion=1` 分别演进。

## 1.0 之后的候选方向

- 更丰富的对象浏览与 SQL 编辑辅助。
- 更强的批量任务观察、恢复和审计能力。
- 更多结果格式与下游数据交换方式。
- 可选的企业连接入口、代理和密钥管理集成。

这些方向以真实痛点和新契约需要为前提，不改变 1.0 已承诺的本地优先与显式操作原则。
