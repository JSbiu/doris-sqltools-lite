# 1.0 发布门禁

本清单用于判定是否可以发布 `1.0.0`，不是命令目录。每项记录三类结果：

- **通过**：本轮已有命令输出、文件、截图或实际操作证据；在“证据”栏写明检查日期与结果。
- **阻断**：未完成，或发现会阻断主流程、影响数据正确性/安全、破坏稳定契约的问题；不得发布。
- **不适用（已接受）**：由用户明确接受，写明范围、原因和残留风险。

环境相关项目只使用一次性或非生产目标，不连接真实生产数据库。自动化通过不能代替真实环境、安装与观察记录。证据随发布保留在变更日志或本机记忆；没有证据的方框保持未勾选。

## 发版顺序

1. 完成 A–C，补齐稳定契约与自动化回归。
2. 用非生产目标完成 D；用窗口工作流完成 E。
3. 生成发布候选 VSIX，完成 F 的干净安装与从 `0.9.11` 升级。
4. 用候选版本完成 H 的观察周期；修复阻断项后只复验受影响的门禁，不机械重跑全部环境。
5. 冻结文档与 skill，更新版本、变更日志和 README，重新执行受版本影响的 B、F、G。
6. 按授权提交并推送 `origin/main`；交付记录明确区分已证实结论、推测和未验证范围。
